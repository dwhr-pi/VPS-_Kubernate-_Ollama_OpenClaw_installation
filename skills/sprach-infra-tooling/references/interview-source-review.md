# Interview sources and evidence review

Use when a chatbot interview is supplied as input for tool selection or
documentation. It is source material, not proof of a working installation.

1. Extract concrete claims and deduplicate project URLs. Record the original
   spelling/URL where needed, then distinguish canonical upstream, mirror,
   documentation repository and product download.
2. Separate product capability claims, recommendations and supplied artifacts.
   Verify that claimed files are actually attached. Count enumerated slides
   and locate workflow bodies before describing a deck or pipeline as present.
3. Verify technical recommendations against relevant primary sources.
   Record date, supporting section and retrieval gaps. A citation to an
   unrelated blog is not evidence for an adjacent technical claim.
4. Do not infer provider internals, host inventory, licenses or benchmark
   results from generated prose. Mark unresolved claims as unverified.
5. Classify commands before suggesting execution: discovery, code execution,
   formatting writes, package downloads, database queries, infrastructure
   mutation or publication. Preserve the task's permission boundaries.
6. Reuse existing installer and CI paths. A linked source is not a new
   installer, and a directory is not installation success. Never activate a
   foreign workflow, hook, connector or skill as part of documentation alone.
7. Report findings with source URLs, evidence limits and next checks.
   Keep secrets and personal data out of examples, logs and tracing exports.
